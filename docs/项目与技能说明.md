# Vibe Workbench 项目与技能说明

> 通用人机交互层：把 AI 与你的协作，从"在聊天框里堆 markdown、等你打字回复"，升级为"AI 把每轮思考渲染成可交互网页，你就地点选/批注/改写，提交即异步唤醒 AI 续跑"。
>
> 设计哲学：**编排注意力 > 渲染内容**。需你决策的上浮、无预设的最先、已设默认的下沉；多轮清楚标出"新增/改了什么"；AI 侧崩了网页也能自救。

---

## 1. 这是什么 / 解决什么问题

聊天流是最弱的一种人机载体：信息线性堆叠、决策点淹没在文字里、你只能用打字回复、AI 断了就黑洞。Vibe Workbench 把"一轮思考"变成一个**可插拔的共享工件**——一个图文网页，按内容类型选对表达（markdown / 架构图 / 选择 / 表态 / 可编辑文档 / 原型），你在网页上就地操作，提交后 AI 被异步唤醒续跑。聊天框只是其中最弱的一种适配器。

## 2. 三种典型用法（这也是"能用它做什么"的直接回答）

| 你要做 | 用哪个模板 | 主力 block | 典型场景 |
|---|---|---|---|
| **开发项目 / PRD 审核** | `dev-review` | verdict(逐条表态) + diagram(架构) + code(Gherkin 用例) | 评审需求条目、架构方案、测试场景，逐条 ✓/✗/? 表态 |
| **UI / 交互设计评审** | `design-review` | prototype(线框/截图/高保真) + verdict/choice + checklist | 看原型/截图，在图上 SVG 定位落 pin 批注、选设计方案 |
| **审阅 / 共创文档 · brainstorm** | `think-discuss` | markdown + editable(就地改写) + verdict + 批注 | 一起写/改文档、讨论思路、做多选决策 |

**结论**：开发项目（含 PRD、交互、UI 设计）与文档审阅，都在能力范围内——分别对应上面三个模板。

## 3. 核心机制

- **注意力四区路由**：每个 block 带 `needsDecision / hasRecommendation / importance / default` 元数据，渲染器据此分区：
  - 需你定·无预设 → 顶部最先看
  - 需你定·有推荐 → 其次（推荐项预选）
  - 纯叙述/图表（无默认）→ 可见的思路区
  - 已设默认 → 折叠"同意即跳过"
- **轮次 diff**：同议题跨轮复用同 block id，自动标 `NEW / CHANGED / 已采纳↩ / 维持—`；顶部「只看变更」过滤；本轮进度「已填 m/X」实时更新；议题重组时顶部横幅提示"diff 仅供参考"。
- **异步唤醒回路**：present 渲染一轮 → 你在网页提交 → feedback 落盘 → listener 认领 → `claude -p --resume` 续跑 → 写回新一轮，网页状态徽章自动变化。
- **容错不黑洞**：文件即状态 + ack 幂等锁 + 启动对账；心跳区分"处理中/离线/出错/服务未恢复"；错误说人话、给可行动作；你的批注永远在磁盘 `workspace/<session>/round-<N>/feedback.json`。
- **embed 就地批注**：把真实网页产物用 `embed` 嵌进来（经 `/api/proxy` 反代绕过 X-Frame-Options），你在页面上**选中文字即评论**（飞书式右栏卡片），或"+ 新增批注"写整体意见。

## 4. block 类型速查

`markdown` · `diagram`(mermaid) · `choice`(单/多选，可带推荐) · `verdict`(✓赞成/✗异议/?疑问) · `freetext` · `editable`(就地改写文档) · `table` · `code` · `embed`(嵌真实产物就地批注) · `prototype`(wireframe/image/iframe，SVG 定位批注) · `checklist`(逐条三态清单)

## 5. 怎么用（技能触发 + 流程）

技能名 `workbench`（触发词：用工作台、present、确认方案、评审一下、让我选、共创文档、把思考给我看）。默认走 **IDE 内辅助模式**（安全、无自动化条款风险）：

```
present 渲染一轮 → 把 URL 发给你 → 后台 wait → 你提交即唤醒 AI → 读 feedback 续跑
```

```bash
WB="/Users/michael/projects/AI 工作流/vibecoding 工作台"
# 1) 组织 content.json（用模板或手写 blocks）
# 2) 渲染并拿 URL（自动确保 server 在跑）
node "$WB/bin/workbench.mjs" present <session> /path/to/content.json
# 3) 后台等提交（提交即唤醒）
node "$WB/bin/workbench.mjs" wait <session> <round>
```

公网工作台作为唯一 workspace 时，在本地 CLI 设置：

```bash
export WORKBENCH_REMOTE_URL='https://workbench.example.com'
export WORKBENCH_TOKEN='云端共享口令'
node "$WB/bin/workbench.mjs" present <session> /path/to/content.json
node "$WB/bin/workbench.mjs" wait <session> <round>
```

远程 `present` 写云端新轮次，远程 `wait` 每 3 秒查询云端 feedback，本地不保留轮次副本。常驻 worker 默认监听本机 `127.0.0.1:8097`；服务端把 `WORKBENCH_EVENT_WEBHOOK` 指向该地址后，轮次、反馈或消息事件会立即触发指定 session 检查，60 秒轮询只作兜底。worker 每 30 秒上报在线心跳，超过 90 秒才显示离线。

> 完整命令、协议、模板签名见 `~/.claude/skills/workbench/SKILL.md` 与本仓库 `docs/DESIGN.md`。

## 6. 架构（三段式"桥"）

```
[ 你 ] ⇄ [ 载体 网页 ] ⇄ [ 内容协议 blocks+feedback ] ⇄ [ 桥 异步唤醒 ] ⇄ [ 接入 CLI ] ⇄ [ Claude ]
         可插拔适配器        不变内核（协议+触发+续接）                 可插拔
```

| 目录 | 职责 |
|---|---|
| `src/protocol/` | 内容协议：schema / diff(轮次差异) / attention(注意力路由) / status(状态判定) |
| `src/server/` | 零依赖 HTTP + API（rounds、content、feedback、status、retry、proxy、事件 webhook） |
| `src/loop/` | 异步唤醒 listener（对账幂等 + 独立心跳 + 容错）/ claude-exec / session-store |
| `src/render/` | 前端：纯函数 HTML 渲染 + 四区注意力 + diff 徽章 + 状态/重试 + 提交确认模态 |
| `templates/` | think-discuss / dev-review / design-review（模板 = block 组合工厂） |
| `bin/workbench.mjs` | CLI：render / present / serve / watch / wait / up |

技术栈：Node ≥20 ESM、**零运行时依赖**（仅内置 http/fs/path/crypto）、前端原生 JS + 本地 mermaid。

## 8. 已知局限 / 下一步（诚实标注）

- **未做真实浏览器 E2E**：现有测试是黑盒 unit/mock，前端交互（模态/进度/embed 选区/异步唤醒整链）尚无浏览器端到端验证——已知的历史 bug 恰恰是真机才暴露的。
- **要当"澄清台"还缺 block 类型**：现协议擅长"对已成形方案做评审决策"，但"从模糊到清晰的前置澄清"（结构化澄清问题、Given-When-Then 验收标准、情绪板/参考图）表达力不足，建议补 `clarification` / `acceptance-criterion` 等。
- **embed/proxy 脆弱**：quote 定位对重复文本不精确；CSP 响应头未完全去除、无 SSRF allowlist；仅可靠支持静态展示页。
- 可访问性（暗色对比度、aria 关联）待一轮系统复核。

> 这些局限来自一次独立多镜头评审，详见调研报告。方向本身（人做编排与验证、AI 做执行、UI 负责把该看的抬上来）与业界 2025–2026 的"spec over vibe / human-in-the-loop"趋势一致。
