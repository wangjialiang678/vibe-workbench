## 2026-06-30 · v2 评审（体验反馈，仅记录，暂不改工具）

用户原话要点：
1. **新旧不分**：第二轮里老内容全量呈现、**新内容没有明显标记**，不知是否遗漏。
2. **决策/非决策分区**：相对确定、已设好默认、**不需要用户决策的放下面**；**需要决策的放上面**。
3. **推荐优先级**：需决策的里，**完全没有推荐的优先告诉我、放最上面**；有推荐的次之。
4. **重要性分级**：再叠加重要性高低排序。

→ 已转化为 FR-7（注意力路由·优先级分区）+ FR-8（轮次差异高亮 diff）。**本条按用户要求仅记录，不立即修改工具。**

## 2026-06-30 · 浏览器 dogfood 发现（已修）

1. **静态目录 404（P0，已修）**：server 对 `/render/`（目录请求）先加 `.html` 再判目录，导致 `src/render` 变 `src/render.html`→404，自然 URL 打不开页面。修：先判目录回退 index.html，再做 .html 回退；加回归测试。
2. **AI 思考被折叠（P1，已修）**：纯叙述/图表（!needsDecision 且无 default）被错误归入"已设默认"折叠区并显示"无默认值"，把 AI 的核心思考藏起来。修：注意力路由新增 `zoneContext`（叙述/图表 → 顶部可见、不折叠），折叠区只收真正"已设默认"项；加单测 + 视图验证。
   → 这两条只有真实浏览器渲染才暴露，印证 dogfood 价值。

## 2026-07-13 · user-vibeloop 项目协作实战（四轮会话 + 真实闭环运维）

来源：Michael 要求 user-vibeloop 项目"所有沟通走工作台"，当天跑了 4 轮决策会话 + 嵌入真实系统操作，收获六条反馈（原始记录在 user-vibeloop 仓 `.claude/memory-bank/research/workbench-feedback-log.md`）：

1. **决议要自带上下文（R1）**：AFX 处置决策块因背景不足，用户被迫在没看懂的情况下选择（"我不清楚 AFX 是什么…每个决议需要更多上下文和背景信息"）。
   → 已在 vibeloop 侧落地（决策卡带 AI 四维自评）；对工作台的建议：choice/verdict 块增加结构化"背景"区约定，或作者侧 lint 提醒。
2. **技术配置块劝退非技术决策者（R2）**："感觉看不太懂这些信息"（verify/riskTiers 的 yaml 映射块）。建议：块级"受众标记"（决策者视图 vs 技术视图），或约定技术细节一律折叠。
3. **术语一致性（R2）**："票应该是工单吧"。作者侧术语表/一致性检查的价值。
4. **缺常驻"给 AI 留言"入口（R2）**：用户的自由反馈只能挂在某个不相干块的批注上（该条反馈本身就挂在 Mac Studio 块下）。建议：会话级常驻 freetext，随提交一并回传。
5. **live embed 与样例无法区分（R4）**：嵌入真实运行系统后，用户误以为"这是给我看的样例"。建议：embed 块支持 `live: true` → 渲染"⚡ 实时系统"角标/边框态。
6. **embed 代理丢 POST 表单体（R4，功能 bug，有探针实证）**：嵌入页内提交表单，`adminToken` 字段丢失致 403；同表单同口令直连原页则通过。`/api/proxy` 对 POST 的 body/Content-Type 透传缺失。修复前 embed 只适合"看"，操作类页面应引导直连。

> 洞察：4 与 6 组合出一个模式——工作台目前是"AI 问、人答"的单向结构，用户主动发起的通道（自由留言、在嵌入系统里直接操作）都还不顺。下一步演进方向可能是"双向工作台"。
