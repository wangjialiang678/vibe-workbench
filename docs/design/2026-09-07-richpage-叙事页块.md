# richpage · 叙事页块（设计 v1，2026-09-07）

> 动机（Michael 原话要点）：工作台/评审台的决策"碎片化、上下文不完整、术语化"，给客户评估很难；希望 agent 在需要展示较多内容时，能相对自由、可视化地呈现一整页——像 claude artifact 那样分节、有表格图表、视觉上把每段分开；给 guideline 但不卡死。
> 勘察结论（2026-09-07）：现有 11 种块**无一接受原始 HTML**（自研 md 引擎先转义后渲染，全系统无 sanitizer）；块类型是插件注册表（`src/protocol/block-types/index.mjs`），注册一个文件即获得校验/渲染/指纹/lint。
> **设计裁决：不放行原始 HTML；新增结构化块 `richpage`，用受控但丰富的词汇表达长文可视化页面，由工作台自身渲染器画出。** 原因：同源页面持有 token，放行 HTML=XSS 主开口；结构化能自动继承 theme.css tokens 与响应式；每节自带锚点可批注。自由 HTML 的沙箱 iframe 模式留 v2。

## 1. 协议

```jsonc
{
  "id": "b-panorama", "type": "richpage", "title": "VibeLoop 全景与路线",
  "summary": "结论先行：一段 markdown（可选，lint 建议必填）",
  "toc": true,                      // 可选，默认 sections≥4 自动出目录
  "sections": [
    { "id": "built",                 // 节内唯一 slug（跨轮复用同 id，供锚点与 diff）
      "heading": "一、已建成并在运行的",
      "kicker": "平台底座",           // 可选：节眉小标
      "items": [                     // 有序原语列表，按顺序渲染
        { "kind": "md",      "body": "markdown 正文" },
        { "kind": "table",   "columns": ["能力","状态","说明"], "rows": [["核心闭环","在运行","…"]] },
        { "kind": "pills",   "items": [ { "label": "在运行", "tone": "ok" }, { "label": "实现中", "tone": "doing" }, { "label": "待拍板", "tone": "wait" } ] },
        { "kind": "kpi",     "items": [ { "value": "40", "label": "发现" }, { "value": "37", "label": "独有" }, { "value": "0", "label": "误报" } ] },
        { "kind": "callout", "tone": "wait", "title": "需要你拍板", "body": "markdown" },   // tone: ok|doing|wait|neutral
        { "kind": "lane",    "title": "近期 · 三件先试", "body": "markdown（列表/表格均可）" },
        { "kind": "steps",   "items": ["markdown 步骤 1", "markdown 步骤 2"] },
        { "kind": "bars",    "unit": "条", "series": [ { "label": "独有发现", "value": 37 }, { "label": "重复", "value": 3 } ], "max": 40 },
        { "kind": "diagram", "lang": "mermaid", "body": "flowchart LR; A-->B" }
      ]
    }
  ],
  "sources": [ { "n": 1, "text": "来源说明", "url": "https://…" } ]   // 可选：正文不放 URL，来源集中文末编号
}
```

**校验（服务端 validate，硬门）**
- `sections` 必填、1–40 节；`section.id` 必填 slug `^[a-z0-9][a-z0-9-]{0,40}$` 且块内唯一；`heading` 必填
- `items[].kind` 白名单：md / table / pills / kpi / callout / lane / steps / bars / diagram；未知 kind 拒绝
- 所有文本字段只能是字符串；`table` 复用现有 table 块的 columns/rows 校验；`diagram` 复用现有 diagram 校验；`bars.series` 1–20 项、value 为有限数
- 尺寸上限：整块序列化 ≤ 256 KiB；单节 items ≤ 60
- **禁止任何字段承载可执行内容**：全部文本经 `mdToHtml`（md 类字段）或 `escHtml`（标签/数值类字段）渲染，`<script>`/事件属性/`javascript:` 必须以文本形式出现在渲染结果里（测试断言）

**指纹/差异**：`hashFields` = title/summary/sections/sources 全量；跨轮同 block id + 同 section id 时，差异视图按节高亮变化。

**lint（软提示，不阻断）**：缺 `summary` → warning「叙事页建议结论先行」；某节 items 为空 → warning；正文 md 里出现 `http(s)://` → warning「链接请集中到 sources」；任一节正文超过 ~1500 字且无子结构 → warning「考虑拆节或用表格」。

## 2. 渲染

- 位置：`src/protocol/block-types/richpage.mjs`（validate + render + hashFields + lint），渲染可拆 `src/render/richpage.mjs`
- 结构：`<article class="richpage">` → 可选 summary 卡 → 可选 TOC（sections≥4 或 toc:true）→ `<section id="rp-<blockId>-<sectionId>" class="rp-section">`（heading 带 kicker）→ items 按 kind 渲染
- 样式：新增 `.richpage` 命名空间 CSS 到 `src/render/app.css`，**只用 theme.css 已有 token**（字号阶梯/间距/圆角/颜色变量），不引入新颜色常量；pills/callout/kpi 的三种语义色（ok/doing/wait）若 theme.css 无对应变量，新增 3 个变量到 theme.css 并注明用途
- 响应式：table 外包 `.rp-tablewrap{overflow-x:auto}`；kpi 为可换行 grid；420px 断点下 kpi 变单列、bars 标签换行
- `bars`：服务端生成内联 SVG 横条（宽度按 value/max 百分比），文本走 escHtml；不引入图表库
- `diagram`：复用现有 mermaid 渲染路径
- `sources`：文末「来源」列表，编号 + 文本 + 裸 URL（`<a rel="noopener" target="_blank">`），URL 仅允许 http/https（校验）

## 3. 批注锚定（D31 统一交互标准：点哪批哪）

- v1 两级：① **节级**：每个 `.rp-section` 标题右侧沿用现有批注 rail 入口，反馈载荷 `{ blockId, sectionId }`；② **选区级**：在 richpage 内选中文字 → 复用 embed 的 quote 机制（`submit-payload.mjs` 的 `{quote}`），只是选区来自主文档而非 iframe（在 `app.mjs` 增加对 `.richpage` 内 `mouseup`+`getSelection` 的监听，载荷 `{ blockId, sectionId, quote }`）
- 高亮回显：与 embed 同级别 best-effort（CSS Highlight API + 文本查找），不做持久化 DOM 锚定
- 决策关联：richpage 默认 `needsDecision:false`（叙事/上下文块）；attention 路由把它视为"上下文块"——与同轮 choice/verdict/checklist 同屏；决策块可在 `background` 里用 `[[#section-id]]` 引用本轮 richpage 的节（v1 只渲染成页内锚点链接）

## 4. 写作指南（进 docs/authoring-guide.md，是建议不是硬门）

- 结论先行：`summary` 写"看完这页你应该知道的三件事"
- 一节一个问题；节标题用人话陈述句，不用内部代号
- 对比用 `table`，状态用 `pills`，2–4 个关键数字用 `kpi`，警告/待拍板用 `callout`（tone=wait），分阶段路线用 `lane`，流程用 `steps` 或 `diagram`
- 面向决策者一律大白话（D36）；术语首次出现给一句解释；案例先交代背景
- 正文不放 URL，来源集中 `sources`
- 段落 3–5 句；每节可以一段"本节小结"收尾
