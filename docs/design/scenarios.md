# 用户场景（scenarios）

驱动 UX 自审与测试计划。每个场景含：步骤、Happy / Error / Boundary。

## S1 think-discuss 思考共创（主场景）

**角色**：用户与 AI 就某设计/想法迭代。
**步骤**：AI 把一轮思考渲染成图文页（markdown 思路 + 架构/时序图 + 若干决策点 + 可编辑文档块）→ 用户在网页对决策点选/表态、对文档就地改、任意处批注 → 提交 → AI 被异步唤醒、据反馈续跑、生成下一轮 → 用户在网页看到「已回复」并查看新一轮。
- Happy：完整跑通一轮往返；提交内容被正确读取并影响下一轮。
- Error：网络/服务器不可达 → 前端降级导出 JSON，用户可手动喂回。
- Boundary：用户只批注不决策；超长文本；一轮含 20+ blocks。

## S2 dev-review 研发评审

**步骤**：AI 用 dev-review 模板渲染 PRD 条目/架构图/测试场景 → 用户逐条 ✓/✗/? + 批注 → 提交 → AI 据反馈改 PRD。
- Happy：逐条 verdict + 评论被正确汇总。
- Error：部分条目未表态（用默认/标记未决）。
- Boundary：大量条目时注意力路由是否把"需决策无推荐"上浮。

## S3 注意力路由（贯穿）

**步骤**：一轮含混合 block（部分需决策无推荐、部分需决策有推荐、部分已设默认）→ 渲染后页面顶部=需决策无预设、其次=需决策有推荐、底部折叠=已设默认 → 顶部状态条显示「需你决策 X 项（Y 项无预设）」。
- Happy：三区归属与区内重要性排序正确；点状态条锚点跳到区 A。
- Error：全部都是已设默认 → 顶部提示「无需你决策，确认即可」。
- Boundary：全部都需决策无推荐 → 区 C 为空、不显示折叠区。

## S4 多轮 Diff

**步骤**：进入第 2 轮 → 新增 block 标 NEW、改动 block 标 CHANGED、未变无标记 → 用户开「只看变更」只看 new/changed。
- Happy：四种变更态标注正确；只看变更过滤正确。
- Error：上一轮数据缺失 → 全部视为 new（不报错）。
- Boundary：本轮全部 unchanged → 只看变更后列表为空 + 提示。

## S5 AI 侧崩溃恢复（web-only 自救）★关键

**步骤**：用户在网页提交后，AI 侧 listener 异常退出 → 网页状态徽章变 🔴 离线（提交已保存，恢复后自动处理）→ listener 被监管重启 → 启动对账发现未 ack 的提交 → 自动补处理 → 网页变 🔵 已回复。或用户点「重试」主动重新触发。
- Happy：崩溃后重启自动补处理；用户全程仅看网页、未回 IDE。
- Error：AI 处理单轮抛错 → 写 error.json → 网页显示 ⚠️ + 错误信息 + 「重试」；点重试后恢复。
- Boundary：心跳过期阈值边界（30s）；重复提交/重复重试幂等（ack 锁防重复处理）。
