# 解耦 / 分层 / 模块化重构 · 2026-08-22

起因：`theme.css` 那次视觉解耦之后，创始人问「项目里还有哪些可以解耦、分层、可扩展和模块化的地方」，
量完代码给出七条，拍板「直接改掉」。本文是派工规格。

**这是纯重构：外部行为一个字节都不能变。** 基线 `npm test` = **593 passed / 0 failed**。

## 包 A · 前端解耦（app.mjs 纯逻辑外提 + block 类型插件化）

**文件域**：`src/render/`（除 `app.css` / `theme.css` / `_lab/`）、`src/protocol/`、`templates/`、`tests/unit/`
**不许碰**：`src/server/`、`src/loop/`、`src/*.mjs`（仓库根下的领域模块）、任何 CSS

### A-1 把 app.mjs 里的纯逻辑搬进可测模块

目标：`app.mjs` 只剩「拿 DOM、绑事件、调纯函数」，判断与计算全部外提。
每个新模块都是纯函数，**不碰 `document` / `window` / `localStorage`**，需要就作为参数注入。

必须新建（模块名可微调，但职责边界照此划）：

| 新模块 | 从 app.mjs 哪一段来 | 必须导出的纯函数（示例，按实际代码定） |
|---|---|---|
| `src/render/draft-store.mjs` | 「草稿」段（约 584–611）+ 草稿恢复段（约 1180–1260） | `draftKey(session, round)`、`mergeDraft(prev, patch)`、`readDraft(storage, key)`、`writeDraft(storage, key, draft)` —— storage 作参数注入，不直接摸 localStorage |
| `src/render/round-nav.mjs` | 「轮次解析 / 自动推进」段（约 2290–2338） | `pickRound(urlRound, latestRound)`、`nextRoundTitle(round, appTitle)`、`shouldAdvance(currentRound, statusRound)` |
| `src/render/pin-geometry.mjs` | 「prototype SVG pin 定位批注」段里的坐标计算（约 1273–1475） | 归一化坐标 ↔ 像素坐标互转、pin 落点计算、越界钳制。纯数学，入参是数字与矩形，不是 DOM 节点 |
| `src/render/facet-state.mjs` | 「tab 分面导航」段（约 2121–2290）里的**状态计算**部分 | 当前分面解析、各分面未答计数、角标等级（must/optional/done）。注意 `tests/unit/facet-nav.test.mjs` 已存在，新测试与它不要重复覆盖同一断言 |
| `src/render/submit-payload.mjs` | 「提交」段（约 1921–2121）里**组装 feedback 载荷**的部分 | 由「草稿 + 块清单」算出 `items[]` 与 `unanswered[]`。**入参是数据不是 DOM**：调用方先把 DOM 读成普通对象再传进来 |

要求：
- 每个模块配 `tests/unit/<模块名>.test.mjs`，覆盖正常值、边界值、异常值。
- `app.mjs` 改为 `import` 这些模块并调用，**逻辑原样搬，不要顺手改行为**。
- 搬完后 `grep -c "^export" src/render/app.mjs` 可以仍是 0（它是入口脚本，不需要导出），
  但**新模块必须有导出且被单测直接调用**。
- 把 `tests/unit/render.test.mjs` 里针对**已搬走逻辑**的「源码正则匹配」断言，换成对新模块的行为断言。
  没搬走的部分保持原样，不要删。

### A-2 block 类型插件化

现状：加一个 block 类型要同时改 `protocol/constants.mjs`（类型清单）、`protocol/schema.mjs`（校验）、
`protocol/lint.mjs`、`render/blocks.mjs`（渲染 switch）、`render/app.mjs`（事件绑定）、
`protocol/attention.mjs`（分区规则）、`templates/*.mjs`。七处，漏一处就出静默 bug。

改成**一种类型一份清单**：新建 `src/protocol/block-types/` 目录，每个类型一个模块，导出统一形状：

```js
export default {
  type: 'checklist',
  validate(block) { return [/* 错误信息数组，空数组=通过 */]; },
  hashFields: ['items', 'verdictLabels'],   // 参与内容哈希/diff 的字段
  render(block, helpers) { return '<html…>'; },
  bindEvents(root, block, ctx) { /* 可选：该类型的交互绑定 */ },
};
```

配一个 `src/protocol/block-types/index.mjs` 做注册表，导出 `BLOCK_TYPES`（由各清单的 `type` 汇总而成）、
`getBlockType(type)`。原有的 `constants.mjs` 的 `BLOCK_TYPES` 改为从注册表转发，**对外名字和值都不变**。

`schema.mjs` / `blocks.mjs` / `lint.mjs` 改为查注册表分派，删掉各自的 switch / if 链。

验收标准：新增一个 block 类型时，**只需在 `block-types/` 加一个文件并在 index 注册**，
不必改 schema / blocks / lint / constants。请在 `tests/unit/block-registry.test.mjs` 里
用一个**虚构类型**证明这一点（注册后校验、渲染、哈希都能走通；测试结束移除，不污染真实注册表）。

⚠️ 注意：`attention.mjs` 的分区规则是按 `needsDecision`/`hasRecommendation`/`default` 判的，
**与 block 类型无关**，不要把它塞进类型清单。

## 包 B · 服务端解耦（路由拆分 + 通知模块外提）

**文件域**：`src/server/`、`tests/e2e/`、`tests/unit/`
**不许碰**：`src/render/`、`src/loop/`、`src/*.mjs`、`templates/`

### B-1 `handleRequest` 拆成路由表 + 端点模块

现状：`server.mjs` 第 1075–2267 行是一个函数，里面顺序 if/else 串了约 20 个端点：

```
/api/health  /api/status  /api/content  /api/rounds  /api/feedback  /api/messages
/api/stream-events  /api/documents  /api/attachments  /api/assets  /api/proxy
/api/participants  /api/participants-public  /api/sessions  /api/session-context
/api/projects  /api/control-tower  /api/inbox  /api/retry  /api/worker-heartbeat
```

改法：

1. 新建 `src/server/routes/` 目录，按领域分文件（建议：`health.mjs`、`session.mjs`、`feedback.mjs`、
   `stream.mjs`、`documents.mjs`、`assets.mjs`、`proxy.mjs`、`participants.mjs`、`projects.mjs`、
   `control-tower.mjs`、`inbox.mjs`、`worker.mjs`、`pages.mjs`）。
2. 每个模块导出 `routes`：一个 `{ method, path, handler }` 数组，`handler(ctx)` 接收一个上下文对象
   （至少含 `req, res, url, query, identity, token, body 读取器, json 响应器` —— 照现有代码实际用到的来）。
3. `server.mjs` 里 `handleRequest` 收缩为：**前置处理（CORS / 安全头 / token 解析 / identity 解析）→ 查路由表 → 分派 → 404 兜底**。

**⚠️ 顺序敏感，这是本包最大风险**：现在的 if/else 有隐含的**匹配优先级**和**鉴权前置**。
拆之前先把现有顺序完整读一遍并在 `src/server/routes/README.md` 里写下来：
哪些端点必须先过 token、哪些是公开的（如 `/api/participants-public`）、
哪些用 `startsWith` 前缀匹配（`/assets/`）因而必须排在精确匹配之后（或之前）。
**拆完后行为必须与拆前完全一致** —— 特别是「无 token 时返回 403 而不是 404」这类差别。

### B-2 通知外提

把 `postWebhookEvent` / `emitWebhook` / `dispatchExecutorEvent` 及相关常量从 `server.mjs`
搬到 `src/server/notify.mjs`，导出干净接口，配 `tests/unit/notify.test.mjs`。

**只搬不加**：不要顺手加多订阅者、重试队列、事件过滤这些没人要的能力（见 AGENTS.md「不做过度设计」）。

## 包 C · 小活（驱动统一 + 文档页暗色清理）

**文件域**：`src/loop/`、`docs/项目与技能说明.html`、`tests/unit/`
**不许碰**：`src/render/`、`src/server/`、`src/*.mjs`

### C-1 AI 驱动选择收敛到一处

现状：`agent-exec.mjs` 有 `resolveAgent()`（已能在 `claude` / `workbuddy` / `codex` 间选），
但 `listener.mjs` 第 112–113 行又自己读了一遍 `process.env.WORKBENCH_AGENT` 做小写归一，
第 141 行还有一处按 agent 名分支的 `switch`。两处逻辑重复，改一处漏一处。

改法：`listener.mjs` 不再直接读 `WORKBENCH_AGENT`，一律通过 `agent-exec.mjs` 暴露的函数拿。
需要什么就在 `agent-exec.mjs` 补导出（如 `configuredAgentName(env)`）。
`switch (agent)` 里那些「按驱动给用户话术」的映射，收进 `agent-exec.mjs` 或单独的
`src/loop/agent-messages.mjs`，用一张表代替 switch。

配 `tests/unit/agent-resolve.test.mjs`：env 未设 / 设了合法值 / 设了非法值三种情况，
断言 listener 与 agent-exec 拿到的是同一个结果。

### C-2 清掉文档页的暗色残留

`docs/项目与技能说明.html` 第 13–16 行有 `@media (prefers-color-scheme:dark)` 整段，删掉。
这是独立静态页，自带 `<style>`，不引 app.css —— 顺手把它的字体栈也补上中文字体，
行高提到 1.75 以上（见 AGENTS.md「中文排版四条底线」）。
